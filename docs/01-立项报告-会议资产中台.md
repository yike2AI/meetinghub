## 一、项目摘要

| 事项 | 说明 |
| --- | --- |
| 建设内容 | 会议资产中台：自动汇集战略会与重点项目会的完整内容，经 AI 提炼为决策、承诺、风险三类结构化资产，提供复盘问答、复盘报告、议题时间线与检索溯源四项能力 |
| 立项缘由 | 会议是公司决策密度最高的场景，但会议内容缺乏系统性沉淀，决策依据难以追溯、承诺事项缺乏对照、复盘工作缺少事实底座 |
| 实施方式 | 不自建会议系统，对接钉钉/飞书/腾讯会议现有录制转写能力；第 1 周完成 POC，第 2 周上线试运行，此后按周迭代，预计 4~6 周达到验收标准 |
| 资源投入 | 本部门 2 名工程师，不新增编制；现金支出为云端模型与服务器费用，每月千元级，无硬件采购 |
| 核心价值 | 决策链路可追溯、承诺事项可闭环、组织记忆资产化，并为公司后续 AI 应用建立组织上下文数据底座 |

## 二、立项背景

### 2.1 问题

公司每月召开的战略会及各区域重点项目会，持续产生高价值决策信息：方向性判断的依据、被否决的备选方案、各责任人的承诺事项、会上识别的风险。上述信息目前散落于各会议平台的单场纪要中，缺乏统一沉淀与关联管理，由此产生三类反复发生的管理成本：

1. **承诺缺乏对照**：会议决议与承诺事项无跨会议追踪机制，执行悬空往往在产生后果后才被发现；
2. **决策难以追溯**：数月后复盘"当时基于何种判断、否决了哪些方案"，只能依赖当事人记忆，人员变动即造成上下文流失；
3. **复盘缺少底座**：战略复盘与项目复盘缺乏完整、可检索的事实依据，材料准备依赖人工翻查零散纪要。

### 2.2 业内实践

该方向已在国内外得到验证。国外方面，Otter.ai 于 2026 年将此类产品定义为"会话知识引擎"新品类，其核心立论为：企业已有 CRM 沉淀客户数据、ERP 沉淀财务数据，唯独会议中产生的决策与上下文长期缺乏记录系统；桥水基金十余年来录制全部内部会议用于决策复盘与管理培训，将其视为决策质量的基础设施。国内方面，飞书、钉钉、腾讯会议的单场 AI 纪要功能已经成熟并被大规模使用，但**跨会议、跨时间维度的决策资产管理仍属空白**——单场纪要无法回答"某项决策的完整来龙去脉""某项承诺在后续会议中是否有下文""某个议题半年来如何演变"。

本项目即定位于此空白：不重复建设会议工具，在现有平台之上构建会议内容的资产层。

## 三、建设内容与总体框架

### 3.1 总体框架

```
钉钉听记 / 飞书妙记 / 腾讯会议纪要（现有平台，API 自动拉取，人工导入兜底）
        ↓
统一会议档案库（逐字稿原文永久留存，所有结论可回查原文）
        ↓
AI 结构化提炼：决策（结论/拍板人/依据/备选项）· 承诺（事项/责任人/期限）· 风险
        ↓  配套人工确认机制：AI 提炼结果由指定确认人校正后入库
        ↓
四项产品能力
```

### 3.2 四项产品能力（1.0 交付）

1. **复盘问答与研判分析**：选定项目范围后以自然语言提问（如"该决策当时的依据与备选方案""哪些承诺事项在后续会议中再无进展""哪些议题多次讨论仍未形成结论"），系统基于该项目全部历史会议内容作答，每项结论附原文出处，可即时核验；项目页面常驻"悬空承诺、议而不决、活跃风险"三类洞察卡片，异常信号主动呈现。
2. **月度复盘报告**：战略会结束后 72 小时内自动生成报告初稿，内容包括本期决策/承诺/风险清单及上期议题的本期进展对照，经项目负责人审校后呈报。
3. **议题时间线**：以议题为线索，完整呈现其在历次会议中的讨论演变过程。
4. **检索与溯源**：全文检索历史会议内容，检索结果一键定位至逐字稿原文。

### 3.3 运行流程（以月度战略会为例）

会前，决策层可查看战略会空间的洞察卡片（如"3 项承诺事项近两月无后续进展"），并可就任一事项追溯清单与原文出处；会中无需任何额外操作；会后 48 小时内确认人完成 AI 提炼结果的校对，72 小时内复盘报告初稿呈报。整个流程对参会人员无干扰，对决策层无使用门槛。

## 四、实施方案

### 4.1 实施原则

1. **对接而非自建**：会议录制与转写使用各平台现有能力，本项目仅做数据拉取与增值处理，显著收窄建设范围与风险；
2. **可信优先**：AI 提炼结果必须附原文证据，无法提供证据的内容一律不予入库；设置人工确认环节与修订留痕机制；原文永久留存，支持事后复核；
3. **小切口验证**：1.0 版本仅覆盖试点会议（月度战略会、战略头脑风暴会及 2~3 个由区域负责人提名的重点项目会，每月合计不超过 20 场），验证有效后再行推广。

### 4.2 交付节奏

| 阶段 | 时间 | 交付内容 |
| --- | --- | --- |
| POC | 第 1 周 | 导入历史战略会存量材料（约几十场），完成"导入—提炼—时间线—问答"全链路内部演示 |
| 上线试运行 | 第 2 周 | 钉钉免登、权限隔离、确认流、复盘报告、复盘问答全部可用，试点范围投入真实使用 |
| 迭代调优 | 第 3 周起 | 按周迭代，预计 4~6 周达到验收标准后向总经理正式演示 |
| 后续版本 | 视验收情况 | 1.1 腾讯会议自动接入；1.5 执行闭环（承诺事项与待办系统联动，另行立项）；2.0 全区域推广及模型私有化部署 |

### 4.3 数据安全

- 按会议空间实施密级隔离：战略会内容仅限高管范围可见，项目会内容仅限项目组可见；系统访问实行白名单制，全部操作留有审计日志；
- 1.0 版本使用国内合规云端大模型，签署数据不用于训练的企业协议；模型调用层采用可替换架构，2.0 版本视情况切换为私有化部署，实现数据不出内网。

## 五、投入与预期价值

### 5.1 资源投入

| 项目 | 规模 | 说明 |
| --- | --- | --- |
| 人力 | 本部门 2 名全栈工程师；前 2 周全时投入，调优期约 50% 投入 | AI 辅助开发模式，不新增编制 |
| 模型费用 | 预估每月 500 元以内 | 试点会议量下的云端 API 用量 |
| 服务器 | 每月约 300 元 | 使用公司现有云资源（4C16G 单机） |
| 硬件采购 | 无 | 私有化部署待 2.0 阶段另行评估 |

### 5.2 预期价值

1. **决策链路可追溯**：每项决策的依据、备选方案与形成过程完整留痕并可回查原文，为战略复盘与决策审计提供事实基础，这是现有任何工具不具备的能力；
2. **承诺事项可闭环**：跨会议自动对照承诺事项与后续进展，使"会上定的事"处于持续可见状态，降低执行悬空带来的管理损耗；
3. **组织记忆资产化**：核心会议的决策上下文沉淀为公司数字资产，不随人员变动流失，历史积累随时间持续增值；
4. **企业 AI 数据底座**：会议是组织上下文密度最高的数据源，本资产库可为公司后续引入的各类 AI 应用提供统一的组织知识基础；同时本项目为部门沉淀智能体开发的工程底座，可复用于后续 AI 项目。

需要说明的是，上述价值以决策质量与资产积累为主要衡量维度，属长期性、结构性收益；项目投入规模有限，风险敞口小，具备充分的尝试价值。

## 六、需公司层面支持的事项

1. **会议纪律**：纳入试点范围的会议须开启云录制/AI 听记功能，建议以总经理要求的形式明确——录制数据是本项目成立的前提条件；
2. **平台权限审批**：钉钉、飞书开放平台的企业应用注册与数据读取权限，需 IT 管理员配合，立项通过后即行发起；
3. **腾讯会议企业版资质确认**：1.1 版本自动接入的前提条件；
4. **历史材料收集**：过去 6~12 个月战略会的存量纪要或录音（约几十场），用于第一周数据回灌。

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 系统建成后使用不足，沦为存档工具 | 洞察卡片与月度报告形成固定触达节奏，每月产出面向决策层的交付物，形成使用闭环 |
| AI 提炼错误影响系统可信度 | 原文证据强校验、人工确认流、修订留痕；报告经负责人审校后呈报 |
| 敏感内容泄露 | 空间密级隔离与白名单访问；云模型签署数据协议；架构预留私有化切换路径 |
| 参会人员因内容留档影响发言坦率 | 仅沉淀结论性内容（决策/承诺/风险），不做发言归因与个人层面分析 |
| 平台权限审批周期不可控 | 保留人工导入通道，确保上线进度不受外部审批阻塞 |

## 八、验收标准（上线后 2 个月）

1. 试点会议 100% 入库，历史战略会材料完成回灌，议题时间线具备 6 个月以上纵深；
2. 连续产出不少于 2 期月度复盘报告并呈报，获得继续建设、扩大范围的反馈；
3. 复盘问答与洞察卡片在实际工作中至少 3 次发挥作用（追回悬空承诺、回答决策溯源类问题等）；
4. AI 提炼结果的人工修正率不高于 30% 且呈逐月下降趋势。
